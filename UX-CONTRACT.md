# Vantagallu UI behavior ownership

## Canonical UI Map

| Capability       | Canonical owner                            | Source of truth                                                 | Allowed variants                                                                  | Verification                                                                      |
| ---------------- | ------------------------------------------ | --------------------------------------------------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Select/Listbox   | Native select in KitchenApp                | Runtime language and library filter state                       | Language, region and diet; OS-owned popup                                         | Keyboard selection and four-language browser checks                               |
| Form             | KitchenApp shared dialog and validateForm  | Controlled drafts, validity state and actual callback result    | Chat, sign-in, serving, cookware, cooking setup and adaptation forms              | Inline error, invalid-field focus and pending submission tests                    |
| Textarea         | KitchenTextarea                            | Controlled draft                                                | Shared auto-grow 80–240px with resize disabled and visible overflow               | Draft preservation and narrow viewport checks                                     |
| Dialog           | KitchenApp native dialog                   | Modal state and actual dialog open state                        | One modal with title, Escape, backdrop close and native focus containment         | Escape and focus-restoration browser checks                                       |
| Feedback         | Runtime props and KitchenApp inline status | Real API, save, voice, chat and authentication state            | Pending, saved locally, saved to cloud, offline, error                            | Provider failures and disconnected-health browser checks                          |
| Voice companion  | Cooker.tsx + existing voice controller     | Actual VoiceStatus, availability, transcript and error props    | Idle, connecting, listening, speaking, reconnecting, error; static reduced motion | State-only component harness, visible Pause voice in modal, no invented amplitude |
| Scrollbar        | src/index.css and src/styles/kitchen.css   | Global CSS thumb, track, hover and forced-colors rules          | Ingredient rail and dialog geometry                                               | Narrow viewport and keyboard scrolling                                            |
| Session changes  | Domain commands and authenticated API      | Revision-checked session state plus durable command IDs         | Guest local storage, signed-in cloud, queued offline changes                      | Domain, runtime, API and live database tests                                      |
| Timer            | Domain deadlines and TimerControl          | Original occurredAt, absolute deadline and pause/resume state   | Start, pause, resume, cancel and restart with a new timer ID                      | Offline replay and expired-timer regressions                                      |
| Source selection | RecipeLibrary and recipe preview           | Source-linked recipe version and authoritative session snapshot | Inspect a method or start a new session                                           | Sources before start and saved-version tests                                      |

Forms declare noValidate. Validation reads field validity, displays an application-owned inline error, associates it with the invalid field and moves focus there. Native validation bubbles are not invoked. Drafts stay intact when a callback fails.

Cooking setup uses the same pantry/stove fields before starting and during an active session. Have/Missing availability is separate from added ingredients; confirmed additions are locked as available. Saving commits setup before requesting model adaptation. Guests can save locally; only an actual connected, signed-in model response may claim to adapt or revise the plan. Closing a preview customization does not discard its draft. Heat guidance displays gas flame levels or approximate induction starting watts up to the selected 1800 W maximum; the app does not control appliances or infer doneness.

Other ingredients I have is a bounded pantry-notes field, not a cooking action or an instruction to add those items. The signed-in preview offers Cook & adapt when missing ingredients, induction or pantry notes require review, and makes exactly one adaptation request after the new session saves.

The UI represents confirmed cooking state; its pan illustration is not a sensor. Expired timers do not establish food doneness. Microphone transport, provider credentials and authenticated persistence belong to the client controller and backend, not the drawing components.

When a newer recipe version exists, an updated-method notice opens the existing source preview for that version. Starting it creates a new cooking session; existing session snapshots, confirmed ingredients and progress are never silently rewritten.

The recipe ingredient list owns a named, keyboard-focusable scroll region. On desktop it scrolls vertically in the right rail; phones retain a bounded horizontal counter. The board and document retain natural height for long instructions. Talk/Type/Next remain anchored and reachable regardless of ingredient count, with reserved page padding so content can scroll above them.

Voice pause closes microphone capture and transport without ending the cooking session. The shared dialog exposes its own Pause voice action while active because native dialogs make outside controls inert. COOKer's organic blob reflects actual voice state, with a static idle/error appearance and static reduced-motion treatment. It is not an audio-level meter. Guest chat has an in-dialog Sign in to chat action that preserves the draft. Account switches invalidate in-flight responses and clear the previous account cache. Conflicted offline updates retain both local and cloud copies and block automatic overwriting until reviewed.

Open voice view is available before the cooking surface. The shared dialog expands the same COOKer component and includes the current recipe step. Starting voice opens this view within the Talk click gesture. Back to recipe closes only the view; Pause voice stops capture and transport. The recipe ID, saved context and confirmed actions survive either action.

Reduced-motion disables decorative movement without changing cooking state. Android uses the same shared dialogs and saved-session runtime, with app-owned Back handling and native microphone permission. Backgrounding pauses voice; it does not finish the cooking session or stop its absolute timers. The web app remains installable as a PWA. Background listening and reliable native alarms are outside this release.
